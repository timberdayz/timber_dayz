A

最小界面修补

保留当前指标表和“维护”抽屉，仅将平台、店铺 ID 改为下拉选择。

•改动少，交付快
•仍混合规则、范围与数据录入
适合只解决手填身份字段的紧急补丁。
推荐
B

两步月度工作台

保留“评分规则”，新增“月度店铺范围确认”和“店铺数据录入清单”。

•完整解决手填店铺、漏录与保存歧义
•可复用现有店铺覆盖与结算模型
适合当前上线前的正确业务闭环，改动受控。
C

独立运营绩效域

新建独立月度记录、审批和快照模型，彻底替代当前目标分解承载方式。

•长期模型最清晰，支持复杂审批
•迁移与结算改动范围大
适合二期重构，不适合当前发布窗口。

B 的用户路径

评分规则指标、评分方向、20 分分配、统一目标值
→
月度范围确认全部启用店铺，管理员标记参与或不参与
→
店铺数据录入参与店铺逐项输入实际值或人工评分
→
校验与结算完成率、待录入项、锁期后不可修改
