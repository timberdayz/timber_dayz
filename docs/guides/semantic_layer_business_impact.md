# 语义层改造的业务影响说明（运营版）

> 读者：业务运营、店铺运营负责人。
> 目的：用业务语言说明这一轮「数据口径治理」改了什么、看板上的哪些数字会变、
> 哪些**不会**变，以及遇到空白格子时该怎么办。
> 技术细节不在本文范围，需要时请找数据平台组。

---

## 一、一句话总结

这一轮我们没有改动任何**业务规则**，而是把「同一件事在不同报表里叫不同名字、
取数时又悄悄按 0 处理」这个长期问题，从根上统一掉了。

对运营最直接的影响是：**以前某些格子显示 0，现在要么显示真实数字，要么显示空白**。
空白的意思是「源表里没有这个数据」，不是「业务上是 0」——这两者在以前是分不清的，
这正是过去大家对着数字吵架的根源。

## 二、订单域：新增两个看得到用得上的字段

### 1. 联盟/达人佣金

| 项 | 说明 |
|---|---|
| 字段名 | 联盟/达人佣金 |
| 之前 | **没有这个字段**。佣金只有一个笼统的「平台佣金」，达人的钱和平台的钱混在一起 |
| 现在 | 单独拆出来 |
| 覆盖平台 | Shopee（联盟佣金）、TikTok（达人佣金） |

**为什么要拆**：一笔订单里，平台抽成和付给达人的佣金是两笔完全不同的钱。
以前只有一个「平台佣金」字段，达人佣金要么没被采集、要么被算进了平台成本。
现在两边各归各家：**平台佣金仍然进平台成本口径，联盟/达人佣金单独看**，
所以**利润数字没有变化**。

**实测数据**（2026-11 开发库）：

- Shopee 联盟佣金：29,629 行订单全部有值，单笔均值 0.76 元，合计 22,519.01 元
- TikTok 达人佣金：4,589 行有值，均值 -3.85 元，合计 -17,662.47 元（负数是平台抽走的口径，见下方备注）

> 备注：TikTok 达人佣金在源表里就是负数表示（平台从达人收入里扣），
> 沿用源表口径，未做符号翻转，避免与平台报表对不上。

### 2. 卖家总收入

| 项 | 说明 |
|---|---|
| 字段名 | 卖家总收入 |
| 覆盖平台 | TikTok |
| 之前 | **没有这个字段**，只有一个含义模糊的「总成交额」 |

**为什么需要**：运营真正关心的不是「买家付了多少钱」，而是「这一单卖家总共收到多少钱」。
这两个数字在 TikTok 上**只有 12% 的订单相等**——差得很远，所以不能混用。

**实测数据**：TikTok 5,254 行订单中 4,054 行有值（77%），单笔均值 79.47 元，合计 322,153.92 元。
剩下 23% 是源表本身没填，不是我们丢的。

### 3. 回款金额的归属被明确了

TikTok 的「回款金额」= 总收入 − 各项费用 = **卖家实际到手的钱**，
实测与「总收入 + 总费用」的吻合率是 59.17%。所以它归到「已结算金额」这个标准字段，
和 Shopee 的「已结算金额」是同一件事。

Shopee 的「预估回款金额」是**预估**值（只有 36% 的行有值），
和「已结算金额」不是一回事，**没有合并**。

## 三、哪些数字**没有变**（重要）

以下是我们逐条核对过的硬指标，**改造前后完全一致**：

| 指标 | Shopee | TikTok |
|---|---|---|
| GMV | 44,284.69 | 9,811.54 |
| 订单数 | 629 | 138 |
| 利润 | 11,520.99 | 3,699.21 |
| 平台成本合计 | 219,325.13 | -6,479.59 |

也就是说：**GMV、订单数、利润、平台成本这四类数字，这轮一个都没动。**
新加的两个字段是「往外加信息」，不是「改算法」。

## 四、历史查询模型（Metabase）里的数字修正

⚠ 这一节只影响**还在用 Metabase 查数**的同学。系统主看板走的是 PostgreSQL 数据链路，
不受影响。

Metabase 的订单模型是手工写的取数逻辑，和语义层各走各的。这次发现它有两个问题：

**问题 1：Shopee 的「实付金额」一直是 0**

模型的取数代码找的是「实付金额 / 买家实付金额」这两列，但源表里的真实列名是
**「买家支付」**——名字对不上，代码没报错，直接按 0 落库。

| | 改造前 | 改造后 |
|---|---|---|
| Shopee 实付金额合计 | 0.00 | 1,993,149.50 |

**问题 2：TikTok 的「实付金额」是外币数字**

| | 改造前 | 改造后 |
|---|---|---|
| TikTok 实付金额合计 | 1,458,557.59（原币，约合人民币的 3.63 倍） | 402,284.04（人民币） |

**为什么这两个数字现在可以信了**：改造后的模型改为「问语义层要数」，
不再自己手写一串列名去猜。语义层只有一份别名表，改一次两边同步。

**给运营的提醒**：如果你之前用 Metabase 看过 Shopee 的实付金额，
看到的 0 是**假 0**，不是业务事实；TikTok 的数字是**外币**，没有换算成人民币。
现在两个都是可以直接用的口径。

## 五、新增了一个「体检面板」

**位置**：数据一致性验证页面 → 新增「语义覆盖率巡检」标签页。

它回答一个问题：**某个标准字段，在源表里到底解析得出来吗、解析率多少、
源表里这一列到底叫什么名字。**

以前想知道这些，只能找数据平台组跑脚本，现在自己点开就能看。
面板会按「哪个平台最差」排序，直接把问题字段和它的真实列名列出来。

## 六、遇到空白格子怎么办

| 现象 | 含义 | 处理 |
|---|---|---|
| 数字从 0 变成真实值 | 以前是取数没对上（列名写错），现在对了 | 直接用新数字 |
| 数字从 0 变成空白 | 源表里确实没有这一列/这一项数据 | **不要当成 0 参与计算**，需要的话找数据平台组确认 |
| 新增的列全是空白 | 该平台源表没有上报这个指标 | 属于正常 |

**一条原则**：这一轮之后，**空白 = 不知道，0 = 真的是 0**。
以前这两种情况在报表里长得一模一样，这是过去最容易被误读的地方。

## 七、流量看板（访客 / 曝光 / 点击）的数字变化

流量域也按同样的标准做了治理：**取数统一走别名表，解析不出来就是空白，不再伪装成 0**。

### 变化最大的三处

| 指标 | 之前 | 现在 | 说明 |
|---|---|---|---|
| TikTok 曝光量 | 0 | **5,736,040** | 之前是**假 0**：取数找的是「曝光次数」，真实列名是「商品曝光次数」 |
| TikTok 点击量 | 0 | **239,334** | 同上（真实列名是「商品点击量」） |
| Shopee 曝光/点击/GMV/订单数 | 0 | 空白 | Shopee 这份流量报表**根本没有**这些指标 ⇒ 空白才是正确答案 |

### 一处需要运营特别注意的口径调整

**TikTok 的「访客数」现在是空白，数字请看「商品访客数」。**

原因：TikTok 的流量报表里，访客类指标只有「商品访客数」这一列（商品级），
**没有店铺级的访客数**。以前系统把商品级访客数当成「访客数」显示，属于口径混淆，
现在如实分成两个字段。

- Shopee 完全不受影响：「访客数」（519,212）和「页面浏览数」（1,115,071）数字不变。

### 一个从 0 变成真实值的指标

**Shopee 的「跳出率」**之前显示 0（取数找的是「跳失率」，真实列名是「跳出率」），
现在显示真实值。

### 完全没变的部分

| 项 | 数值 |
|---|---|
| 流量域行数 | Shopee 2355 / TikTok 1446 |
| Shopee 访客数合计 | 519,212 |
| Shopee 页面浏览数合计 | 1,115,071 |
| TikTok 页面浏览数合计 | 234,577 |
| TikTok GMV 合计 | 1,095,058.35 |
| TikTok 订单数合计 | 3,490 |

订单域的 GMV / 订单数 / 利润 / 平台成本也**完全没有变**（见第三节）。

### 月度流量看板（同一套口径）

月度报表和日/周报表来自**同一份源表**，所以月度看板也一起做了同样的治理，
数字不会和日/周看板对不上。以下是 2026-11 月度段的实测：

| 指标 | 月度之前 | 月度现在 |
|---|---|---|
| TikTok 月度曝光量 | 空白 | **119,462** |
| TikTok 月度访客数 | 2,764（其实是商品访客数） | **空白**（TikTok 无店铺级访客数） |
| TikTok 月度商品访客数 | 2,764 | **2,764**（不变） |
| TikTok 月度页面浏览数 | 3,296 | **3,296**（不变） |
| TikTok 月度 GMV | 15,430.87 | **15,430.87**（不变） |
| TikTok 月度订单数 | 103 | **103**（不变） |
| Shopee 月度访客数 | 2,463 | **2,463**（不变） |
| Shopee 月度页面浏览数 | 4,645 | **4,645**（不变） |

> 月度口径与日/周口径**完全一致**：同一个指标在两条链上取的是同一个列。

## 八、这一轮没做的事

- 没有改变任何利润、GMV、成本的计算口径。
- 没有改动 Shopee / TikTok 之外的平台。
- 没有删除任何历史字段（老字段仍然能查到，只是新增了更准确的）。
- 流量看板（访客数、曝光、点击等）的口径本轮已按同样标准治理完毕，
  变化见第七节（含月度看板）；**已确认的 GMV 与订单数同样没有改变**。
- 直播/视频 GMV 那一族指标（商家直播 GMV、达人视频 GMV 等）源表里确实有，
  但还没有对应的标准字段，**本轮没有登记** ⇒ 报表里看不到它们。
  这不是丢了，是「有列名、无语义」，等定义了标准字段再补，避免一列多名。
  ⚠ 补登前必须先定口径：实测这 12 个 GMV 归因列**相加 = 总 GMV 的 1.57 倍**
  ⇒ 它们**互相重叠**（同一笔成交被多个归因维度各算一次），
  所以**绝不能默认它们可以相加**。在「每列单独看占比」的口径确认之前，
  一列一个标准字段、绝不聚合。

## 九、Shopee 独有的 5 个流量指标（本次新接进语义层）

Shopee 的流量报表里还有 5 个指标，之前**既没有标准字段、也没进语义层** ——
语义层取不到它们，所以下游任何报表都算不出。
现在**语义层取数链路已打通**：

| 新字段 | 源表列名 | 含义 | 实测（Shopee 月度源表 2,354 行） |
|---|---|---|---|
| 新访客数 | 新访客 | 访客里「第一次来」的那部分 | 合计 444,991 |
| 现有访客数 | 现有访客 | 访客里「之前来过」的那部分 | 合计 74,221 |
| 新关注者数 | 新关注者 | 本期新增关注的人数 | 合计 1,319 |
| 平均停留时长（秒） | 平均停留时长 | 一次访问平均停留多少秒 | 0~215 秒，均值 36.5 秒 |
| 平均页面访问数 | 平均页面访问数 | 一个访客平均看几页 | 均值 1.62 |

> ⚠ **本轮只做到「语义层能取到」**：日/周与月度的流量事实表（`semantic.fact_analytics_*`）
> 已经输出这 5 列，体检面板里也能看到它们的解析率；
> **月度/日周看板（`mart.platform_month_kpi` 等）还没有把这 5 列铺出来** ——
> 要在看板上直接看到，需要另开一轮改看板视图。

三件实测出来、可以拿数字做保证的事：

1. **「访客数」== 「新访客」+「现有访客」**，2,354 行**全部精确相等**（误差 0）。
   两个数加起来正好是 Shopee 的访客总数 519,212 ⇒ 可以放心相减。
2. **「平均停留时长」在源表里是 `时:分:秒` 字符串**（形如 `00:00:42`），**不是数字**。
   我们把它**换算成秒**再入库。
   ⚠ 如果按普通数字清洗，`01:30:00` 会被读成 `13000`（把小时当成了数值）——
   这类错很隐蔽（数值看着还挺合理），所以单独处理。
3. **「平均页面访问数」≈「页面浏览数」÷「访客数」**，1,814 行可用数据**全部**落在 ±0.02 内。

TikTok 的流量报表里**没有**这 5 列（1,374 行里一个都没有），
所以它们被登记为 **Shopee 专属**指标 —— TikTok 那边是**空白**，不是 0。

> 日报/周报与月报取的是**同一个列、同一套清洗规则**，实测合计完全一致：
> 新访客 444,991 / 现有访客 74,221 / 新关注者 1,319 /
> 停留时长 85,932 秒 / 平均页面访问数 3,819.93。

## 十、采集范围与已知缺口（请运营注意）

这一轮把「流量数据到底采到了哪」也查清楚了：

| 项 | 情况 |
|---|---|
| 采集触发方式 | **全部手动**（所有采集任务的定时开关都是关闭的） |
| 近 7 天采集成功率 | 约 48%（16 成功 / 8 失败 / 8 取消 / 1 部分成功） |
| 失败主因 | **Shopee 登录态**：打不开 seller.shopee.cn 登录页（网络超时、登录组件执行失败、浏览器被关掉） |
| TikTok | 最近三次（11-05 / 11-07 / 11-08）**全部成功** |

两处**真实缺口**（不是取数问题，是数据没采到）：

1. **TikTok 2026-08 整月缺失**：月度表与日报表都是 0 行。
   如果后续只重采 10 月和 11 月，8 月这一格会**一直空着**。
2. **TikTok 11 月只到 11-06**：月度桶里只有 01~06 日共 6 天。

另外提醒一个容易踩的坑：两个平台月度表的「日期」含义**不一样** ——
Shopee 的月份桶里放的是**按天**的行，TikTok 的月份桶里放的是**整月每日数据堆在每月 1 号**。
所以「2026-11」这个月，Shopee 覆盖 7 天、TikTok 覆盖 6 天，
**两边的月度数字不是同一批日期**，横向对比时要留意。

## 十一、这一轮**没有**改变的东西（再强调一次）

- 订单域的 GMV / 订单数 / 利润 / 平台成本：**一字未变**（见第三节）。
- 流量域**既有**指标的取值：一个都没动，本次只是**加列**，没有改任何旧列。
- 本次新增的 5 个指标**只在 Shopee 侧有值**，TikTok 侧是空白 ——
  没有把 TikTok 的「没有」写成 0，也没有反向套用 Shopee 的口径。
