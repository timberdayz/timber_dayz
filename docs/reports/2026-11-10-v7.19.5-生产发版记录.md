## 1. 本版本做了什么

一句话：**把「服务器磁盘只增不减」和「Redis 抖动冻住全站」这两件事治了，顺带修了一个静默失效的预览缺陷。**

| # | 内容 | 类型 | 影响面 |
|---|---|---|---|
| 1 | 网关文件日志开始轮转（logrotate） | 运维 | 服务器磁盘 |
| 2 | 回滚/暂存资产保留策略上线 | 运维 | 服务器磁盘 |
| 3 | Celery 派发移出 API 事件循环 | 运行时 | API 可用性 |
| 4 | 预览表格路径规范化/合并单元格还原修复（F821 真缺陷） | 运行时 | 数据预览页 |
| 5 | 采集组件白名单对齐实际资产（v7.19.4 之后累计） | 准确性 | 无运行时影响 |
| 6 | 根 `tests/` 的 PG 契约用例全量进 CI 常态门禁（v7.19.4 之后累计） | 工程 | 无运行时影响 |

运行时行为变化只有两处（#1 #2 只影响磁盘占用，#3 不改发布时机/参数/失败语义）。

## 4. 过程中被 CI 抓到的一个真问题（已修，记录在案）

第一轮 CI（run `42790848883`）的 `test (3.11)` **红在两个既有 fail-closed 守护用例**上：

- `backend/tests/test_remote_deploy_migration_contract.py::test_remote_deploy_requires_frontend_and_gateway_health_before_declaring_cutover`
  ⇒ `assert 67649 < 33007`
- `tests/test_prod_release_fail_closed_contracts.py::test_deploy_script_backs_up_before_running_the_migration`
  ⇒ `assert 5088 < 2790`

**根因（实测定位）**：这两个用例用 `script.index(...)` 取**字面量的首次出现位置**。
本轮新增的**说明性注释**里出现了同样的标识符（`DEPLOYMENT_CUTOVER_COMPLETE=1`、
`perform_pre_migration_backup`）⇒ 锚点被提前 ⇒ 断言误判为红。**不是新代码的行为问题**，
两个守卫要守护的顺序性质本身没有被破坏。

**处理原则**：**不动既有守卫**（语义与牙齿完全不变），改的是本轮自己新增的**注释措辞**。
复跑 45 文件门禁 = 388 passed / 2 skipped。
