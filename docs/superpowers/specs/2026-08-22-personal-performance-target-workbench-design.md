# 个人绩效目标工作台设计

## 背景

现有个人绩效输入项允许按员工自由维护指标。一旦存在输入项，当前计算会以该输入项总分替代店铺继承绩效，造成店铺经营结果与个人项目之间的口径不清；收入审计页也无法解释个人分来自店铺还是人工输入。

本设计保留店铺绩效作为个人绩效的主来源，将个人目标收敛为固定 20 分的受控月度工作台。店铺运营目标继续属于店铺，不迁移到个人模块。

## 已确认决策

1. 店铺运营目标管理改名为“店铺绩效目标管理”，保持现有自动整数计分、店铺范围、实绩录入和正式结算链路。
2. 新增“个人运营目标管理”，替代 V1 的个人绩效输入项维护入口。
3. 个人最终绩效固定为：

   ```text
   个人绩效总分 = 店铺继承基础分 x 80% + 个人运营目标得分
   ```

   店铺继承基础分范围为 0 到 100；个人运营目标得分范围为 0 到 20。因此最终分范围为 0 到 100。个人运营目标得分不可再乘 20%。
4. 店铺继承基础分来自员工当月有效店铺归属的正式店铺总绩效，按店铺销售目标加权。店铺总绩效已包含店铺运营分，个人模块不得重复加店铺运营的 20 分。
5. 个人运营目标总分固定为 20；按启用目录指标的 `sort_key` 均分，余数优先给靠前指标。分数仅使用整数和 `ROUND_HALF_UP`。
6. V1 个人运营指标全部手工录入；不接自动考勤、培训或目标数据源。
7. V1 不保留管理评价、自由人工总分或任意分值的个人调整项。专项任务采用受控三级结论，不能自由打分。
8. 个人候选范围默认展示全部在职员工。员工必须有当月有效店铺归属，才可确认参与正式个人绩效；无归属员工必须标记为不参与，备注可选。
9. 参与员工缺少任一启用个人指标的实绩时为 `partial`，不得进入正式个人绩效、收入、工资或排名。
10. 已锁期月份不可改规则、范围或实绩。历史月份和旧个人输入保留只读兼容，不自动迁移或改写。
11. 新旧模式以月度计划的不可变 `calculation_mode` 为唯一权威：不存在个人计划时为 `legacy_inputs`；创建个人规则时，服务端在同一事务中创建 `controlled_targets_v1` 计划。已存在有效旧个人输入或旧人工调整的月份不得直接切换，必须保持旧模式；不得以“某月是否已有新记录”动态推断模式。
12. `controlled_targets_v1` 中，所有在职员工都会有范围快照。范围为参与的员工必须完成正式个人绩效；范围为不参与的员工写入 `not_participating` 结果且不阻断其基础工资生成。其既有店铺归属可继续形成独立的提成，不生成个人绩效工资；个人范围绝不阻断全月其他员工的工资处理。

## 个人指标目录

V1 受控目录如下：

| 指标 | `metric_code` | 录入方式 | 固定标准 |
| --- | --- | --- | --- |
| 考勤达标率 | `attendance_compliance_rate` | 手填实际百分比 | 目标 100%，越高越好 |
| 培训完成率 | `training_completion_rate` | 手填已完成/应完成 | 完成率目标 100% |
| 个人目标完成率 | `personal_goal_completion_rate` | 手填实际百分比 | 目标 100%，越高越好 |
| 专项任务完成情况 | `personal_special_task` | `passed` / `partial` / `failed` | `partial`、`failed` 必填说明 |

量化百分比统一按 0 到 100 存储和录入。专项任务达成系数为 `1`、`0.5`、`0`。个人规则页仅允许启用或关闭指标；目标、方向、单位、输入类型、评分说明和排序来自受控目录。

## 月度流程

### 1. 启用个人考核项

管理员选择本月启用的个人指标。系统自动分配 20 分：启用 2 项为 `10 + 10`，启用 3 项为 `7 + 7 + 6`。保存时创建不可变规则快照，至少必须启用一项。

### 2. 确认参与员工

候选为全部在职员工，显示姓名、工号、部门/岗位、当月店铺归属状态、参与状态和可选备注。有至少一个有效 `EmployeeShopAssignment` 的员工可被标记参与；没有归属的员工显示阻断原因，不能参与正式范围。所有不参与员工保留范围快照，备注可空。

确认范围时为每位参与员工冻结完整的归属子快照：平台、店铺 ID、归属比例、角色、销售目标分解 ID 和正销售目标金额。每个纳入快照的店铺必须有正销售目标；任一有效归属不满足此条件时拒绝确认该员工。后续店铺归属、比例或目标调整不得改写已确认月份；正式计算只读取该归属快照。

撤销范围会清除个人实绩草稿和归属子快照，但保留规则草稿。

### 3. 录入个人实绩

只展示已参与员工。管理员针对每名员工填实际业务数据，界面实时展示单项自动分、个人运营总分、完成状态和公式。全体参与员工的必填指标完整时，该月个人目标才可进入正式计算。

## 数据与接口边界

新增独立个人目标领域，不复用 `SalesTarget`、`TargetBreakdown` 或旧 `EmployeePerformanceInput` 作为 V1 写入目标：

- `a_class.personal_performance_metric_catalog`：版本化受控目录。
- `a_class.personal_performance_plans`：每月规则头，保存规则版本、目录版本和 20 分规则快照。
- `a_class.personal_performance_employee_scopes`：每月员工参与范围与身份/归属快照。
- `a_class.personal_performance_assignment_snapshots`：参与员工的冻结店铺归属、比例和销售目标权重。
- `a_class.personal_performance_entries`：每名参与员工、每个启用指标的结构化输入与计算结果快照。

提供与店铺工作台对应的契约：

- `GET/PUT /performance/personal-workbench`
- `GET/PUT /performance/personal-workbench/scope`
- `POST /performance/personal-workbench/scope/revoke`
- `GET/PUT /performance/personal-workbench/entries`

所有写接口复用工资锁期校验和乐观锁冲突语义。所有影响同一月份绩效或工资状态的写入，必须在同一数据库事务持有同一期间级 PostgreSQL advisory lock，并在写入前最终复检工资锁期；工资确认也必须使用该锁。旧 `/hr/employee-performance-inputs` 在新模式月份只读或返回明确的迁移提示；旧月份仍走既有兼容路径。

同一期间锁的覆盖对象包括：个人规则/范围/实绩、店铺运营规则/范围/实绩、员工店铺归属、当月店铺销售目标及其分解、绩效重算和工资确认。所有这些写路径必须在锁内完成最终状态校验，不能只在请求开始时做存在性检查。

## 最终计算与审计

个人结算服务先验证已确认的个人范围、冻结归属快照及所有店铺正式绩效，再计算：

```text
店铺继承基础分 = sum(店铺正式总分 x 店铺销售目标) / sum(店铺销售目标)
店铺贡献分 = 店铺继承基础分 x 0.8
个人最终分 = clamp(店铺贡献分 + 个人运营目标得分, 0, 100)
```

分母只来自确认时快照的正销售目标。确认时任何参与员工存在零、负或缺失销售目标都会被拒绝，运行时不得回退到实际销售额或常量权重。

内部保留计算精度；API、绩效页和收入审计页统一展示 1 位小数。`EmployeePerformance` 增加或使用结构化详情快照，以区分 `store_inherited_base_score`、`store_contribution_score`、`personal_operation_score`、各个人指标和最终分。工资和收入只消费 `complete` 的最终个人绩效。`not_participating` 员工可生成基础工资与其独立店铺提成，但个人绩效工资为零且不进入个人绩效排名。

`EmployeePerformanceInput` 和 `EmployeePerformanceAdjustment` 都不参与新模式月份的计算；它们的创建、修改、停用接口在 `controlled_targets_v1` 月份必须拒绝，前端只读显示历史记录。历史数据只读保留。未来如需主观奖惩，必须作为版本化、受控指标另行设计，不能绕开个人目标工作台。

## 前端

- 新增 `/target-management/personal` 的“个人运营目标管理”工作台，复用店铺工作台的三步交互结构。
- 将旧“个人绩效输入项”从日常个人绩效管理页移除，保留历史月份只读查看。
- 个人绩效结果页和收入审计页展示完整分解，而不是仅展示原始浮点总分。
- 店铺运营页面文案更新为“店铺绩效目标管理”。创建店铺目录 V3（四项）后，未来月份使用 V3；现有 V2 及已确认月的规则快照继续可回放，培训完成率只出现在个人目录。

## 验收

1. 1 至 4 项个人指标启用时，个人目标满分恒为 20，分配为整数。
2. 范围候选展示在职员工；无店铺归属员工不可确认参与；不参与备注可空。
3. 四类手工输入、专项任务说明、重复键和锁期拒绝均有契约测试。
4. 完整员工按 `店铺基础 x 0.8 + 个人 20 分` 得到最终分；缺失任一店铺或个人维度保持 `partial`，不进入收入和工资。
5. 店铺运营指标不在个人目标目录中；培训不再出现在店铺目录。
6. 审计、列表和工资读取同一最终个人绩效，分数显示统一为 1 位小数。
7. 新模式标识、归属快照、零目标拒绝和期间锁同时覆盖个人工作台、工资确认、重算和审计。
