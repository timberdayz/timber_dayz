① 核心发现

一个字段同时承载「维度 + 区间」

录制的 01 空态截图里，筛选框默认显示的是「创建时间」，日期区是空的。 你必须先把这个下拉改成「更新时间」，日期区才成为你要的那一维。

如果组件只填日期、没先切维度，妙手会用「创建时间」去筛 —— 结果依然是一份看起来正常的清单， 但语义完全错误，而且不报任何错。

② 正确时序

四步，每一步都有可断言的落地信号

组件必须按这个顺序执行，每步之后都验证 DOM 状态再往下走 —— 不能靠 sleep。

  1. 把维度切到「更新时间」
    点开 [data-field='dateRangeType-dateRangeValue'] .jx-select__wrapper， 在浮层 li.jx-select-dropdown__item 里点文案为「更新时间」的那一项。浮层根是 div.jx-select-dropdown.pro-select-popper（内层 ul 是 listbox，选项才是 li）。 这一步不做，日期区间筛的是「创建时间」。
    落地信号 div.jx-select 的 modelvaluegroup 变成 gmtModified,2026-09-04 00:00:00,2026-10-08 23:59:59 兜底判据 浮层里 li.jx-select-dropdown__item.is-selected 的文案 == "更新时间" 失败模式 modelvaluegroup 仍是 gmtCreate,... → 维度没切成功，必须重试不能继续
  2. 填入起止时间
    点第一个 input.jx-range-input（placeholder=开始时间）唤起日期面板， 填 2026-09-04 00:00:00；第二个（placeholder=结束时间）填 2026-10-08 23:59:59。 面板是 div.jx-picker-panel.jx-date-range-picker.has-sidebar.has-time，带 5 个快捷项可替代手填。
    落地信号 两个 input 的 value == 期望值 注意 此刻 modelvaluegroup 还没变 —— 只改了输入框的值，组件内部模型未提交
  3. 点「确定」提交区间
    面板页脚 button.jx-picker-panel__link-btn，文案「确定」 （同级还有一个「清空」是 text 样式，不要选错）。
    落地信号 modelvaluegroup 更新为新值 实测证据 改完 input 未点确定 → modelvaluegroup 仍是旧值； 点确定 → 变为 gmtModified,2026-09-01 00:00:00,2026-10-08 23:59:59 失败模式 跳过这步 → 日期永远不生效，且不报错
  4. 点「搜索」执行筛选
    点 button.J_queryFormSearch（type=submit，class 含 pro-button jx-button--primary）。 现有组件的 _click_search 找的是 get_by_role("button", name="搜索")， 实测页面上确实存在这个按钮，可沿用，但建议加 J_queryFormSearch 作为更稳的 class 兜底。
    落地信号 「SKU总数」和「库存总价值」文本刷新为新值 录制实测 搜索前 1112 / 226239.10 → 搜索后 147 / 31230.57

④ 落到组件上

四条硬要求

要求怎么做为什么不能省
必须先切维度 选 [data-field='dateRangeType-dateRangeValue'] .jx-select__wrapper 点开， 再在 .jx-select-dropdown 里点「更新时间」 默认是「创建时间」。不切 → 筛错维度，页面照样"成功"，静默错误
必须点「确定」 面板内 .jx-picker-panel__footer 里的「确定」按钮 实测：填完 input 不点确定，modelvaluegroup 不变，日期不生效
每步都要断言 切维度后断言 modelvaluegroup 以 gmtModified 开头； 点确定后断言区间已写入 妙手这两处都不报错，不断言就静默采空
搜索后校验 等「SKU总数」/「库存总价值」文本刷新，且 SKU 数 > 0 筛选未生效时页面照常显示旧结果，不校验就会采到全量
好消息：不需要新造轮子

仓库域已有现成的 date_picker.py（apply_custom_range / _range_input / _type_range_inputs）， 订单域的 _ensure_date_range_from_config 就是现成范式。 但它们都要加一步「先切维度」 —— 因为「维度 + 区间」是妙手这两个页面共有的复合控件， 而订单页的日期字段是单维度的。这是本次唯一的新增能力。

⑤ 尚未取证

还剩三件事

  1. 「导出搜索的商品」在筛选态下导出的是不是筛选结果

    这是增量的最后一环。若它导出的是全量，那时间筛选就白做了。 05 号截图只证明菜单存在，没验证导出内容。

  2. 维度下拉的浮层与「仓库」下拉是否同构

    已确认同构（都是 jx-select-dropdown → ul[role=listbox] → li[role=option]）， 但仓库下拉有 header「全选」，本下拉没有（只有 2 个选项）。

  3. 快捷项「近7天/近30天」是否可用作采集入口

    若可用，采集组件可以省掉日期输入，直接点快捷项 → 确定 → 搜索，稳定性会高得多。但快捷项是相对今天，与「水位线推进」的语义要另行对齐。
