Data Sync · 500 事故复盘

「准备同步」时报内部错误 —— 以及这类错误怎么不再犯

表面症状是页面上的一块数据整片变成 --、弹一个红色错误。 真实原因是一次数据库会话被并发使用：接口 500 → 概览拿不到数 → 页面塌掉 → 「同步全部可同步文件」按钮被禁用 → 看着像「同步坏了」。

按「不能修好一次，后续还会发生」的要求，这次做了三道防线： 一处在根上修、两道自动化守卫，漏网的也会被自动捞出来。

一句话根因：同一个 AsyncSession 被多个协程同时用。 SQLAlchemy 明令禁止 —— 一个协程在 commit() 时另一个在 execute()/close()，直接撞出 IllegalStateChangeError，接口 500。
触发条件：待同步文件 ≥ 2 个。之前一直是 0 个（所以从不触发）， 今天采集注册了 3 个 —— 第一次踩上。

现场

后端日志连报 4 次 governance/stats 500，traceback 精确到 get_async_db → session.close()。
Method 'close()' can't be called here; method 'commit()' is already in progress

真正建同步任务的 POST /data-sync/single 实测三个文件都返回 200 并正常建任务 —— 坏的只是旁边那块概览。

三道防线

① 在根上修本次修复
并发的每个协程自己开会话，请求级会话不再进并发区。仓库里早就有这个惯例（data_sync.py:1651 注释写着「每个协程使用独立的数据库会话，避免并发冲突」），这次是把它补齐。
改一次
② 静态守卫CI 门禁
AST 规则扫全仓：识别直接持有（形参/赋值）和间接持有（X = SomeService(db)）请求级会话的变量，一旦在 asyncio.gather / create_task 里被用到就报错。已挂进 scripts/run_lint.py。
每次提交
③ 运行期巡检兜底
静态规则看不穿跨模块传递、方法内部的共享会话、第三方封装。这一层从后端日志里捞 SQLAlchemy 的会话并发异常特征，漏网的也能自动发现，不用等人在页面上看见。

为什么两道守卫自己也要测

守卫如果自己悄悄失效，事故就会原样重演。所以两道都配了自测 （backend/tests/test_async_session_concurrency_guard.py，6 项）：

要守住的性质怎么验
共享 session 必须被报出来喂一段有问题的代码 → 断言报出且指出变量名
独立 session 不能被误报喂「每个协程自开会话」的写法 → 断言不报
同名业务函数不能被误判业务里叫 create_task 的普通函数 → 断言不报
巡检按「事故次数」计数一次事故在日志里是几十行 traceback → 断言只算 1 次

全仓审计：还有没有别的雷

修完之后跑静态守卫：全仓 0 处。 另有两处 asyncio.gather 是 AST 看不穿的（session 在方法内部）， 人工审过，确认安全：

位置为什么安全
backend/tasks/data_sync_tasks.py:282每个协程自己 AsyncSessionLocal()，并在 finally 里 close
backend/domains/business/routers/dashboard_api_postgresql.py:612看板 service 是无参单例，方法内部自开会话，不碰请求级会话
还欠着两件事

① 后端要重启才生效 —— 正在跑的后端进程是 13:30 启动的，加载的还是旧代码。
② 概览接口本身太慢 —— GET /api/data-sync/files 实测慢到 15.6 秒 （3.25 MB 的 xls 每次都全量解析 + 比对表头，日志里刷屏「匹配率 0.0%」）。 读文件这种 CPU/IO 活儿放在 async 里会阻塞事件循环，这次没动，另记。
