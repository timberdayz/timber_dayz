# ==============================================================================
# 生产运行时依赖锁定文件（单一真相源）
# ==============================================================================
# 本文件由生产 v7.12.8 镜像的实测 pip freeze 清单逐字落地，**每个包的版本都是
# 实测值，不是推导值**。生产镜像（Dockerfile.backend / Dockerfile.collection）
# 只安装本文件，不再做任何浮动解析。
#
# 事故背景（v7.12.7）：
#   旧 Dockerfile.backend 分两步安装依赖，根 requirements.txt 用浮动范围
#   （celery>=5.3.0 / redis>=5.0.0），而 celery 的传递依赖 kombu 没被任何
#   文件钉住 -> 两次构建之间 kombu 从 5.6.2 漂到 5.7.0，而 kombu 5.7.0 硬性
#   要求 redis-py>=6.1.0，与钉死的 redis==5.0.1 冲突 ->
#   celery-worker 上线即抛 kombu.exceptions.VersionMismatch 崩溃循环，
#   定时任务（自动入库 / 低库存告警 / 数据库备份）停摆约 30 分钟。
#   pip 在安装期不报这个冲突，所以镜像构建一直是绿的，坏镜像一路推到生产。
#
# 维护约定：
#   1. 本文件 = 生产镜像内实际包集合的唯一真相源。改版本 = 改运行时行为，
#      必须在同一次提交里说明原因（见 docs/guides/RELEASE_CHECKLIST.md）。
#   2. 升级某个包时，必须同步更新：
#        - requirements.lock.txt（本文件）
#        - requirements.txt（若它是运行时直接依赖）
#      两者的版本必须一致，scripts/verify_image_dependency_pins.py 会交叉校验。
#   3. 新增运行时直接依赖时：先在 requirements.txt 里声明，再把它的传递
#      依赖闭包补进本文件，然后重跑镜像校验门禁。
#   4. 开发/测试工具一律放 requirements-dev.txt，**不进生产镜像**。
#      本文件里保留的 pytest / black / flake8 / isort 等历史条目已在
#      v7.12.9 迁移到 requirements-dev.txt，生产镜像不再携带。
#
# 校验门禁：
#   python scripts/verify_image_dependency_pins.py --image <镜像名>
# ==============================================================================
