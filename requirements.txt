# ==============================================================================
# 生产运行时**直接依赖**清单（依赖单一真相源）
# ==============================================================================
# 维护规则：
#   1. 本文件只声明直接依赖，版本一律用 == 钉死，禁止再出现 >= 浮动范围。
#   2. 传递依赖的确切版本全部记录在 requirements.lock.txt —— 生产镜像
#      （Dockerfile.backend / Dockerfile.collection）只安装那一个 lock 文件。
#   3. 本文件的每个版本必须与 requirements.lock.txt 一致；
#      scripts/verify_image_dependency_pins.py 会做交叉校验，不一致即失败。
#   4. 开发/测试工具一律放 requirements-dev.txt，**不进生产镜像**。
#   5. 改版本 = 改运行时行为，必须在同一次提交里说明原因。
#
# 历史（v7.12.7 生产事故）：旧 Dockerfile.backend 分两步装依赖，根清单用浮动
# 范围，celery 的传递依赖 kombu 没被任何文件钉住 -> kombu 从 5.6.2 漂到 5.7.0，
# 而 kombu 5.7.0 硬性要求 redis-py>=6.1.0，与钉死的 redis==5.0.1 冲突 ->
# celery-worker 上线即崩溃循环，定时任务停摆约 30 分钟。
# 结论：凡是没被显式钉死的传递依赖，都会在两次构建之间随上游发版漂移。
# ==============================================================================
